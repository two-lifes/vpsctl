# vpsctl — правила проекта

Дополняют глобальные правила (`~/workspace/CLAUDE.md`). При конфликте действуют правила этого файла.

## Источники правды
- Требования — `docs/SPEC.md` (ID F-xx). Задачи и их статус — `docs/PLAN.md`.
- Стандарт сервера — `docs/SERVER-STANDARD.md`; архитектура и форматы — `docs/ARCHITECTURE.md`.
- Любое изменение принятого решения — новая запись в `docs/DECISIONS.md` (ADR), а не молчаливая правка.
- Работа ведется только через `/next-task`: одна задача из PLAN.md за запуск, затем остановка и отчет.
- Неясно или противоречиво — вопрос в раздел «Вопросы» PLAN.md и пользователю; не придумывать.

## Язык
- Документация и общение — русский.
- Код, комментарии, идентификаторы, сообщения коммитов — английский.
- Коммиты — Conventional Commits (`feat:`, `fix:`, `test:`, `docs:`, `chore:`, `ci:`, `refactor:`), scope по пакету: `feat(sshx): ...`.

## Go
- Последняя стабильная версия Go (версия — в `go.mod`).
- Обязательно: `gofmt`, `go vet`, `golangci-lint` (конфиг `.golangci.yml`), тесты с `-race`.
- Новый код — с тестами. Новая зависимость — только с записью причины в DECISIONS.md.

## Shell-скрипты (bootstrap, vpsctl-deploy, коллектор)
- bash, первая строка после shebang — `set -euo pipefail`.
- Идемпотентность: каждый шаг проверяет, сделан ли он, и повторный запуск ничего не ломает.
- `shellcheck` без предупреждений (без отключений без обоснования в комментарии).
- Тесты — в Docker-контейнерах `ubuntu:24.04` и `ubuntu:26.04`, включая повторный запуск.

## Команды проверки
```bash
gofmt -l .                     # должно быть пусто
go vet ./...
go build ./...
go test -race ./...
golangci-lint run
shellcheck scripts/*.sh scripts/vpsctl-* scripts/lib/*.sh tests/scripts/*.sh   # по мере появления файлов
tests/scripts/run.sh 24.04 && tests/scripts/run.sh 26.04                        # появится в T-1.1
```
Инструменты стоят в `~/.local/bin` (Go — `~/.local/go`). Локально нет Docker: контейнерные тесты выполняются в CI (job `scripts`); это явно указывается в отчете.

## Git
- Ветка на этап: `stage-1`, `stage-2`, … Коммит после каждой задачи. В конце этапа (задача `T-N.gate`) — PR в `main`, слияние только после подтверждения пользователя.
- Без Claude-атрибуции в коммитах и PR.

## Безопасность
- Никаких секретов в репозитории (ключи, токены, пароли, `.env`).
- Никаких действий на реальных серверах пользователя без явного подтверждения в чате — в том числе «только чтение».
